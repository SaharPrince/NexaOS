# NCE-002e: PE Image-Layout Compatibility Review

## Purpose

NCE-002e expands deterministic layout coverage before any relocation or import-resolution work begins. It does not add execution, executable memory, DLL loading, or host-process integration.

## Added compatibility cases

The integration suite `engine/pe-inspector/tests/image_layout_compatibility.rs` constructs explicit PE32+ AMD64 metadata reports and checks:

- A BSS-only section (`SizeOfRawData = 0)) is represented as zero-fill and does not require a file source range.
- An initialized section with equal raw and virtual sizes is copied without an unnecessary zero-fill range.
- Multiple initialized sections retain their independent source offsets and destination RVAs.
- Low section alignment is accepted when `SectionAlignment` is below the page size and equals `FileAlignment`.
- Low section alignment is rejected when the two alignment values differ.

These are synthetic metadata-level compatibility tests. They are not real executable corpus samples and do not establish compatibility with any compiler or application family.

## Current policy still requiring corpus evidence

The planner currently maps `max(VirtualSize, SizeOfRawData)` bytes and copies the complete raw section range when `SizeOfRawData` is larger than `VirtualSize`. Existing unit tests preserve this policy, but it still needs review against legitimate compiler-produced and third-party PE files.

The next corpus pass should use only redistributable samples with clear licensing or files generated by installed compiler toolchains. Record the sample origin, architecture, optional-header kind, section count, alignment values, and whether the planner accepts or rejects it. Do not commit proprietary binaries or samples with unclear redistribution rights.

## Validation status

The new integration tests are committed but are not considered validated until the current branch's formatting, Linux and Windows tests, Clippy, fuzz smoke test, and dependency audit complete successfully.

The Windows CI currently builds and inspects compiler-produced PE32+ AMD64 and PE32 x86 executables for the NCE-001 parser. The NCE-002 image planner remains PE32+ AMD64 only; the PE32 x86 fixture must not be treated as loader coverage.

## Safety and scope boundary

The review remains structural only. It does not execute samples, map executable pages, apply relocations, resolve imports, or load third-party DLLs. The image buffer remains ordinary zero-initialized, non-executable storage.

## Exit criteria

- Synthetic compatibility tests pass on Linux and Windows.
- Existing NCE-001 and NCE-002 regression tests remain green.
- The planner's acceptance and rejection behavior is documented without overstating real-world compatibility.
- A separately tracked, redistributable PE sample corpus is reviewed before NCE-002 is declared complete.
